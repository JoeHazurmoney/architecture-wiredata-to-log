1.0.0rc1 is the release candidate for wd2l 1.0.0, the first release meant for production. It
rehearses the full release with the new release manifest.

## What changed since 0.3.0rc4

0.3.0rc4 is the last complete release: 0.3.0rc5 was tagged but never released, and 0.3.0rc6
was published without its files.

**New in the release itself**

* **A release manifest** in every release: `wd2l-1.0.0rc1-release-manifest.json`, checked
  against a committed schema, and `.md`, its readable view. It lists:
  * the commit;
  * every file with its SHA-256;
  * the image and its base images;
  * the pinned build tools;
  * every issue the release resolves, with the pull request that resolved it.

  `SHA256SUMS`, its signature and the build provenance cover it like every other file.
* **A changelog**, generated with git-cliff and grouped by type: `wd2l-1.0.0rc1-changelog.md`.
* **Retrieval without the forge:**
  * `wd2l-1.0.0rc1-source.bundle` holds the source with its full history;
  * `wd2l-1.0.0rc1-verify-release.py` checks everything offline in one step: the signature, every
    checksum, the manifest, the bundle's commit and, optionally, the image.
* **The notes are generated in full**, from this summary and the manifest.
* **Current pins:**
  * the cosign and Grype tool images, and the UBI 9 and UBI 10 images, move to their latest
    digests;
  * the real-chronyd check runs on Fedora 44.

**In the software** (first released in 0.3.0rc5 and 0.3.0rc6)

* **An arm64 image.** The container image is built for linux/amd64 and linux/arm64, each
  natively on its own runner, and every check runs for both. There is one OCI tar per platform
  (`wd2l-1.0.0rc1-image-amd64-oci.tar`, `…-arm64-oci.tar`), and the SBOMs and vulnerability
  summaries come per platform too.
* **Podman can check the signature itself.** Each platform image is also signed in cosign's older
  format, which Podman's `sigstoreSigned` policy reads. The release workflow checks it, both with
  cosign and under that policy.
* **Container mode works under SELinux.**
  * The Quadlet units no longer mount `/var/lib/wd2l` with `:z`, which relabelled the capture
    archive and stopped host tcpdump writing it.
  * The `wd2l` package labels the directory for containers instead.
  * The units pass `--chrony-addr` once, from the env file.
* **The ARP watcher** reacts only to its own NIC's events, and keeps retrying if it fails.
* **`capture_down_errors`** in the receiver's health summary counts the reads that found the
  capture NIC down.
* **`--max-stratum`** (default 3) sets the time alarm's stratum limit.
* The RPMs order their SELinux scriptlets after `policycoreutils`.

## Upgrading from 0.3.0rc4

* **Native hosts:** run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says. The
  packages relabel `/var/lib/wd2l` themselves.
* **Container hosts:**
  1. After `dnf upgrade`, copy the new `.container` files from `/usr/share/wd2l/quadlet/` over
     yours (no `:z` on `/var/lib/wd2l`, and no `--chrony-addr` in `Exec`).
  2. Check that `grep -- --chrony-addr /etc/wd2l/*.env` finds the option.
  3. Relabel once with `sudo restorecon -RF /var/lib/wd2l`.
  4. Check that `ls -dZ /var/lib/wd2l/pcap` shows `netutils_tmp_t`.
  5. Run `sudo systemctl daemon-reload` and restart.
* **Bringing the image in:** the offline tar's name carries the platform. Take the one for your
  host (`uname -m`: `x86_64` → `amd64`, `aarch64` → `arm64`).
