wd2l 1.0.0 is the first release meant for production. It moves logs one way, from Enclave 1 to
Enclave 2, across a network tap with no return path, and rebuilds them in Enclave 2 with their
original host, source and sourcetype for the SIEM. It's the code of 1.0.0rc1, which was
rehearsed and verified end to end.

## What 1.0.0 delivers

* **The one-way transfer.**
  * `wd2l-sender` numbers every event and sends it over UDP out a NIC with no return path.
  * `wd2l-receiver` rebuilds each event from the captured packets, checks it, and sends it to
    the SIEM. It keeps a capture archive that can be replayed safely.
* **Evidence of completeness:**
  * hash-chained audit records in both enclaves;
  * reconciliation of what was sent against what arrived, with the time on both sides of the
    link;
  * fault location by segment, and a state-of-health dashboard.
* **Two ways to deploy, both verifiable offline:**
  * RPMs for RHEL 9 and RHEL 10;
  * a FIPS container image on Red Hat Hardened Images for linux/amd64 and linux/arm64, run under
    systemd with Quadlet, with SELinux enforcing.
* **A documented supply chain:**
  * signatures that verify without a network;
  * SLSA Build Level 3 provenance;
  * SBOMs, and vulnerability scans with an expiring-exception gate;
  * reproducible builds, and immutable releases.
* **A release manifest** (`wd2l-1.0.0-release-manifest.json`, and its readable view `.md`). It
  is this release's version description:
  * every file delivered, with its SHA-256;
  * the image and its base images;
  * how it was built;
  * every issue resolved since the first commit, with the pull request that resolved it.
* **Retrieval without the forge:**
  * the source with its full history, as a git bundle;
  * a changelog;
  * `wd2l-1.0.0-verify-release.py`, which checks the whole release offline in one step.

## Verifying it

```bash
python3 wd2l-1.0.0-verify-release.py --key cosign.pub --image-tar wd2l-1.0.0-image-<arch>-oci.tar
```

Use a `cosign.pub` obtained from a trusted channel. `docs/releasing.md` lists each check
separately.

## Upgrading

* **From 1.0.0rc1:** run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says.
  On container hosts, bring in the 1.0.0 image and update the `Image=` line. Nothing else
  changed.
* **From 0.3.0rc4,** the last complete release before this one:
  * **Native hosts:** run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says.
    The packages relabel `/var/lib/wd2l` themselves.
  * **Container hosts:**
    1. After `dnf upgrade`, copy the new `.container` files from `/usr/share/wd2l/quadlet/` over
       yours (no `:z` on `/var/lib/wd2l`, and no `--chrony-addr` in `Exec`).
    2. Check that `grep -- --chrony-addr /etc/wd2l/*.env` finds the option.
    3. Relabel once with `sudo restorecon -RF /var/lib/wd2l`.
    4. Check that `ls -dZ /var/lib/wd2l/pcap` shows `netutils_tmp_t`.
    5. Run `sudo systemctl daemon-reload` and restart.
  * **The offline image tar** is one per platform (`uname -m`: `x86_64` → `amd64`, `aarch64` →
    `arm64`).
* 0.3.0rc5 was never released, and 0.3.0rc6 was published without its files. Use 1.0.0.
