1.1.0rc1 is the release candidate for wd2l 1.1.0. It completes the fixes from the review of
1.0.0 that 1.0.1 began, and an operator will see some of them: new health fields, two settings
checked at start, and new exit codes for `wd2l-audit-report`. Upgrade from 1.0.1 in a planned
window, after the checks in "Upgrading".

## What changed since 1.0.1

**Time and completeness (the receiver)**
* **No false clock-skew alarm when a sender stops cleanly.** Since 1.0.1 the sender sends its
  final heartbeat three times, 50 ms apart, and the receiver read the last copy's delay as clock
  skew. Every clean stop raised "WD2L - Time quality" (`clock skew 0.100 s > 0.05 s`), and it
  stayed up until the sender started again. A repeated heartbeat no longer moves the offset.
* **No false clock-skew alarm from a busy receiver.** Each heartbeat's reading is its arrival
  time minus its send time, so a receiver slowed by load or by a capture backlog read the delay
  as skew. The offset is now the lowest of the last 10 readings, and the skew is judged once 3
  are in, the way NTP filters delay. A clock that falls behind still shows at once; one that
  jumps ahead shows up to about 10 s (10 heartbeats) later.
* **A replayed event counts once.** After `output_dropped` or `receiver_restart`, the replay
  counted each refilled event a second time in the reconcile records' `events_delivered`.
  `in_siem` equals `events_delivered` again, as `docs/operations.md` says.
* **Gaps past the receiver's cap are reported.** The receiver keeps at most 100,000 gap ranges
  for a stream, and drops the oldest past that. It now reports what it dropped:
  * `forgotten_gap_events` in the health record;
  * `gaps_forgotten` in the reconcile records;
  * once for each stream, a `gaps_forgotten` health record, an audit event and a warning in the
    journal.

  The "WD2L - Reconciliation not balanced" alert leaves those streams to "Events lost in
  transfer", as it does streams with open gaps.
* **Rule 9 names the receiver's own downtime.** Its detail is now "N events lost, no NIC errors
  or kernel drops: loss on the path, or the receiver was down". Its status and segment are
  unchanged.

**Settings checked at start**
* **The sender's size limits.** `--max-datagram` must be 69 to 65,507 bytes, and large enough to
  carry `--max-event` (at least 1024) in 65,535 pieces. A value outside them is now a usage error
  (exit 2) at start. Before, a `--max-datagram` under 72 failed at the first event, and a small
  `--max-event` stopped with a traceback.
* **Enclave 1's audit records, on a receiver with no audit token.** With `--hec-url` but no
  `--hec-audit-token-file`, the receiver sent them to the SIEM on the data token, which refused
  every one. They now go to the file output (`--out-dir`) only. Without one, they're dropped and
  counted as `records_unrouted`. A warning at start says which. The shipped `receiver.env` sets
  the audit token, so nothing changes there.

**The sender**
* **The per-minute work keeps its own minute.** The health record, the audit summaries, the time
  and free-space checks and the daily self-check ran only when the `--stats-interval` log line
  was due, so raising that interval slowed them all. `--stats-interval` now paces only the log
  line. The default (60 s) behaves as before.
* **The fallback body of an oversized event keeps `_time` only if it's a number.** A very long
  string `_time` made the fallback too big for the receiver too.

**Audit**
* **`wd2l-audit-report` and `python3 -m wd2l.audit verify` exit 2** when the audit directory is
  missing or can't be read, or holds a file they can't read, and say why. Before, `verify`
  reported `failed` (exit 1), and `reconcile` and `events` printed nothing. An empty directory
  still fails, with exit 1.
* **The auditd rules load without warnings.** Each watch is now a syscall rule, for 64-bit and
  32-bit calls, so `augenrules --load` no longer prints "Old style watch rules are slower" for
  each one. They watch the same files, under the same keys. `auditctl -l` lists twice as many
  wd2l rules.

**Verifying a release**
* **`verify-release` works with cosign run from a container** that mounts only the current
  directory, as the wrapper in `docs/releasing.md` does. Before, its image check failed: it
  extracted the image under `/tmp`, which that container can't see. The wrapper's `$TMPDIR`
  mount is now needed only for the `verify-release` of 1.0.1 and earlier.

**The image and the release**
* The image is built on newer digests of the same base images (`hi/python:3.12-fips` and its
  builder).
* **Scan findings pause for a security review** instead of failing the build. Every finding is
  recorded. A fixable High or Critical, or a secret, that no exception covers waits for the
  security owner's approval, in pull requests and releases. An exception lasts at most 90 days
  from the scan.
* **The weekly rescan** of released images scans each one by the digest its manifest records. It
  labels its issues `security` and `bug`, so the next release lists them under Known issues.
* **The release checks more of itself:**
  * a real release's manifest must name its image, its changelog and the release approval;
  * the published image tags are read back;
  * a run can't sign the same image twice.
* **The reproducible-build check now fails the build** on any difference. The sdist's bytes
  change once from 1.0.1's: its members' times, owner and modes are now fixed. Its files are the
  same.
* The cosign that signs releases is pinned to major version 3.

**Documentation**
* The host guides say what `dnf remove` takes and what it leaves, the token files included.
* The option tables match the parsers, and the health docs match the dashboard and alerts.
* `docs/multiple-files.md` no longer says the receiver rebuilds files. It sends events to the
  SIEM; a file rebuild is a separate check.
* The README's "Try it" works where `pip install` is refused, and its `rpm -K` sentence says what
  only the signed `SHA256SUMS` catches.
* `docs/releasing.md` covers the gaps found in the 1.0.0 retrieval drill, and what to do when
  `publish` signed nothing.

## Verifying it

```bash
python3 wd2l-1.1.0rc1-verify-release.py --key cosign.pub --image-tar wd2l-1.1.0rc1-image-<arch>-oci.tar
```

Use a `cosign.pub` obtained from a trusted channel. `docs/releasing.md` lists each check
separately.

## Upgrading

* **From 1.0.1:** run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says. On
  container hosts, bring in the 1.1.0rc1 image and update the `Image=` line. Either enclave can be
  upgraded first: the wire format and its version (1) are unchanged.
* **Copy the auditd rules again, and load them.** On the log server:

  ```bash
  sudo cp /usr/share/wd2l/audit/log-server.rules /etc/audit/rules.d/wd2l.rules
  sudo augenrules --load
  ```

  On the receiver, the same with `receiver.rules`. On container hosts, also copy
  `log-server-quadlet.rules` or `receiver-quadlet.rules` to
  `/etc/audit/rules.d/wd2l-quadlet.rules`. `augenrules --load` should print no warnings.
* **Check the sender's limits** in `/etc/wd2l/sender.env`. A `--max-datagram` outside 69 to
  65,507, or too small for `--max-event`, now stops the sender at start.
* **A receiver with no `--hec-audit-token-file`** never delivered Enclave 1's audit records: the
  SIEM refused them on the data token. They now go to the file output, or are counted as
  `records_unrouted`. To send them to the SIEM, set the audit token, as the shipped
  `receiver.env` does.
* **Scripts that read `wd2l-audit-report`'s exit code:** 2 now also means the directory, or a
  file in it, couldn't be read.
* **The SIEM:** install the new `savedsearches.conf`. The reconciliation alert reads
  `gaps_forgotten`. Records from older receivers lack it, and count as 0.
* **New in the health records:** `forgotten_gap_events` and `records_unrouted`, and the
  `gaps_forgotten` record type. The dashboard needs no change.
* **The cosign wrapper** from `docs/releasing.md` can drop its `$TMPDIR` mount for this
  release's `verify-release`. Keep it for older releases.
* **From earlier releases:** follow the 1.0.1 notes, then the above.
