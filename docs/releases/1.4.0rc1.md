1.4.0rc1 is the release candidate for wd2l 1.4.0. It fixes one false alarm in the receiver, and
adds to what comes with each release:
* the receiver no longer raises a false "capture archive isn't being written" at a start after
  downtime;
* the SBOM page shows where each image came from, from its provenance, and checks it against
  the SBOM;
* the release manifest also comes as a page that opens in any browser, offline;
* the rescan of released images is monthly, over the latest and the previous release, and no
  longer reopens a finding that the latest release fixed.

The image is built on the same base digests as 1.3.0, so its OS packages are 1.3.0's. The
`wd2l` package (the RPMs, the wheel and the image's) has the receiver fixes. The settings, wire
format and SIEM content are 1.3.0's.

## What changed since 1.3.0

**The receiver**
* **No false rule 11 at a start after downtime** (#187). For the first `--hb-timeout` seconds
  after the receiver started, before any packet had arrived, the old capture file counted as
  stale, and the fault status went amber ("the capture archive isn't being written: a replay
  would have nothing") until the sender's own rule outranked it. Rule 11 now waits for a packet
  since the start. Once packets arrive while the archive is still old, it fires as before.
* **No false rule 11 when the sender comes back** (#252). Its first packet could be judged by
  an archive age sampled just before tcpdump wrote it, for one fault interval. The archive is
  now judged against the newest packet seen when it was sampled, so a real stall is caught up
  to 5 s later.

**The SBOM page: where each image came from** (#201)
* **Each image's tab has a "Where it came from" section,** from its provenance: the tag and the
  commit, the workflow and the run, the runners, the wheel by SHA-256, and each base image by
  digest, with its mirror.
* **Two cross-checks with that tab's SBOM,** each shown as "matches" or "does not match":
  * the runtime base in the provenance is the base the image's label names;
  * the wheel in the provenance is the one the SBOM's `wd2l` component was installed from.

  A mismatch fails the release, like any other gap in an SBOM.
* **It's a reading aid, and it says so.** The record is the signed attestation on the image,
  checked by `verify-release`, or by the `cosign verify-attestation` command in
  `docs/releasing.md` ("Bringing a release into an enclave").
* **The comparison image's provenance is a release file now:**
  `wd2l-1.4.0rc1-provenance-ubi9.json`, listed in the manifest and in `SHA256SUMS`.
* The RPM and Python package tabs point to GitHub's build provenance, which covers them.

**The release manifest as a page** (#202)
* **`wd2l-1.4.0rc1-release-manifest.html`** is the same view as the `.md`, as one page that
  opens in any browser, offline: real tables, long digests that wrap, section links at the
  top, and a print layout that keeps each table's header with its rows. It loads nothing and
  runs no script.
* **One renderer makes both views** from the same sections. The `.md` is unchanged, and the
  JSON is still the authoritative record.
* It looks like the SBOM page, and the two link to each other.

**The rescan after release**
* **Monthly, on the 1st,** and over the latest and the previous final release, instead of weekly
  over the three latest (#240). A CVE disclosed just after a rescan is found up to a month
  later. Pull requests and releases always scan with fresh data, and a rescan can be run by
  hand at any time.
* **A finding that the latest release fixed opens no issue** for an older release (#239). It's
  listed in the run's summary as `Fixed in <latest>: upgrade`. The pull request that moves the
  base to a fix closes the rescan's issues, so the next release lists them as resolved.
* **The pins check is its own workflow,** `pin-check.yml`, and stays weekly: a registry can
  delete a retired digest within a day.

**Also**
* A pull request that changes only files under `docs/` skips the lab, the image and the RPM
  jobs. Pytest still runs (#244).
* The expected Trivy warnings about SBOMs in the image give their real cause: pip's two
  CycloneDX files in the base layer, which a later layer deletes (#236).

## Verifying it

```bash
python3 wd2l-1.4.0rc1-verify-release.py --key cosign.pub --image-tar wd2l-1.4.0rc1-image-<arch>-oci.tar
```

Use a `cosign.pub` obtained from a trusted channel. `docs/releasing.md` lists each check
separately. The comparison image's tar is checked the same way, with `--image-tar
wd2l-1.4.0rc1-image-ubi9-amd64-oci.tar`.

## Upgrading

* **From 1.3.0:**
  * run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says;
  * on container hosts, bring in the 1.4.0rc1 image and update the `Image=` line.

  Nothing else changed: the settings, the wire format, the auditd rules and the SIEM content are
  1.3.0's.
* **From earlier releases:** follow the 1.3.0 notes, then the above.
