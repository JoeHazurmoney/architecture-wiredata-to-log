1.3.0rc1 is the release candidate for wd2l 1.3.0. It changes what comes with each release, not
how wd2l runs:
* the release manifest counts the lines changed since the previous final release;
* the image is built on newer base digests, which fix a High vulnerability in expat;
* the release tools are newer.

wd2l's code, settings, wire format, RPM contents and SIEM content are those of 1.2.0.

## What changed since 1.2.0

**The release manifest: lines changed**
* **A new section, "Lines changed since v1.2.0",** counts the lines added, modified and deleted
  since the previous final release, in total and per file type (#224).
  * **How it counts:** from `git diff -M -U0`. In each hunk, the lines both removed and added are
    modified, and the rest are added or deleted. A renamed file counts by its edits only, and a
    binary file as a file with no lines. It's a plain count of lines, not SLOC.
  * **File types:** by extension, or by name for a file with none. Every `Containerfile` or
    `Dockerfile` variant, such as `Containerfile.ubi9`, counts as one type (#226).
* **It names the two commits it compares,** with a link that compares them on the forge (e.g.
  GitLab, GitHub), and the `git diff` command that does the same offline, in a clone of the
  source bundle.
* **The release notes** give the totals in one line, with the same link.
* **The schema:** `changes.diff` is new and optional, so the manifests already published still
  validate. `schema_version` stays 1.

**The image**
* It's built on newer digests of the same base images (`hi/python:3.12-fips` and its builder),
  so Python stays 3.12.
* **They fix CVE-2026-77214 (High) in expat** (2.8.5 to 2.9.0). The weekly rescan reported it
  in the images of 1.0.1, 1.1.0 and 1.2.0 (#218–#223).
* **They also fix CVE-2026-114406 (Medium) in ca-certificates** (2026.2.90 to 2026.2.92).
* **They add no known vulnerability.** The only other packages that changed are rebuilds of the
  same versions of `sqlite-libs` and `pcre2`.

**The UBI 9 comparison image** is built on a newer `ubi9/ubi` digest. It's still not for
deployment.

**The release tools**
* cosign and oras, which sign the release and attach its files, are at newer digests. This is
  the first release they sign.
* grype is 0.121 (from 0.119).
* The pinned UBI 9 test image, setuptools for the build, and two CI actions are newer.

## Verifying it

```bash
python3 wd2l-1.3.0rc1-verify-release.py --key cosign.pub --image-tar wd2l-1.3.0rc1-image-<arch>-oci.tar
```

Use a `cosign.pub` obtained from a trusted channel. `docs/releasing.md` lists each check
separately. The comparison image's tar is checked the same way, with `--image-tar
wd2l-1.3.0rc1-image-ubi9-amd64-oci.tar`.

## Upgrading

* **From 1.2.0:**
  * run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says;
  * on container hosts, bring in the 1.3.0rc1 image and update the `Image=` line.

  Nothing else changed: the settings, the wire format, the auditd rules and the SIEM content are
  1.2.0's.
* **From earlier releases:** follow the 1.2.0 notes, then the above.
