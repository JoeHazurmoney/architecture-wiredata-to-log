wd2l 1.0.1 fixes faults found in a review of 1.0.0, including two that could lose an event or
hide the clean end of a sender run. Upgrade from 1.0.0 in a planned window. The configuration
needs no change, apart from one check on `--hec-url` (see "Upgrading").

## What changed

**The transfer**
* **The end of a sender run survives a lost packet.** The sender now sends its final heartbeat
  three times, 50 ms apart. Before, if that one packet was lost, Enclave 2 reported
  `stream_lost` instead of `stream_end`, and wrote no reconcile record until its hourly pass.
* **A sender paused in the middle of an event no longer loses it.** If the sender stalled
  between two pieces of a split event for more than 5 s (an I/O stall, a paused VM), the
  receiver gave up the event, although every piece arrived. It now waits while the stream sends
  nothing, up to `--stream-lost-after` (60 s). It still gives up an event 5 s
  (`--reasm-timeout`) after its stream has moved on without it.
* **One malformed reply from the SIEM no longer stops delivery.** Before, it ended the delivery
  thread while the receiver looked healthy. Unexpected errors in delivery are now counted
  (`hec_thread_errors`, which rule 10 reports) and retried.
* **A state file that can't be saved no longer restarts the receiver.** It is retried every
  second, and health reports `state_save_failed` until it works.
* **An audit directory that can't be opened at start no longer stops the transfer.** The
  process runs without an audit file until it is fixed and restarted. Health shows
  `audit_ok=false`, and every record is still forwarded, the first an `audit_failure` with
  `reason=open_failed`.
* **`NaN` and `Infinity` are refused** in heartbeats and events, as JSON requires. Before, one
  crafted heartbeat could put the receiver in a restart loop. A number too big for a float is
  dropped from a heartbeat.
* **`--hec-url` must start with `https://` or `http://`.** The receiver now refuses anything
  else at start, instead of failing every post.

**Documentation**
* Moving a log server from a manual install to the RPMs now also removes
  `wd2l-egress-arp.service` from `/etc/systemd/system`. That unit ran from the deleted
  `/opt/wd2l`. See "Upgrading".
* The audit-verify commands in the runbooks run as the `wd2l` user. Run as an administrator,
  they reported a false "failed".
* Planned downtime on container hosts uses `systemctl mask` and `unmask`. Quadlet generates the
  container units, so `disable` changes nothing there.
* The interface description says the final heartbeat is sent three times, and when the
  receiver gives up a part-built event. The wire format and its version (1) are unchanged.

**Release and checks**
* The release signing key is kept only in the release environment, and a check on `main` fails
  if it is ever a repository secret again. Changes reach `main` only as squash merges.
* New checks: a test pins the wire format to the interface description's captured frames, and
  the namespace lab now fails if Enclave 2 tries to send anything.

## Verifying it

```bash
python3 wd2l-1.0.1-verify-release.py --key cosign.pub --image-tar wd2l-1.0.1-image-<arch>-oci.tar
```

Use a `cosign.pub` obtained from a trusted channel. `docs/releasing.md` lists each check
separately.

## Upgrading

* **From 1.0.0:** run `dnf upgrade`, then stop and start as `docs/planned-downtime.md` says. On
  container hosts, bring in the 1.0.1 image and update the `Image=` line. Either enclave can be
  upgraded first: a 1.0.0 receiver already ignores the extra copies of the final heartbeat.
* **Check `--hec-url`** in `/etc/wd2l/receiver.env`. It must begin with `https://` (or
  `http://`), or the receiver won't start.
* **A log server moved from a manual install with the 1.0.0 guide** may still have the old
  ARP-watch unit. If `systemctl cat wd2l-egress-arp | head -1` shows
  `/etc/systemd/system/…`, remove it:

  ```bash
  sudo rm /etc/systemd/system/wd2l-egress-arp.service
  sudo systemctl daemon-reload
  sudo systemctl restart wd2l-egress-nic wd2l-egress-arp
  ```

* **New health fields:** `state_save_failed`, and `hec_thread_errors` among the `hec_*`
  counters. The dashboard and alerts need no change.
* **From earlier releases:** follow the 1.0.0 notes, then the above.
